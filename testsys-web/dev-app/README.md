# Dev-приложение веб-компонентов

Документ описывает самостоятельный модуль `testsys-web:dev-app`: витрину компонентов и демонстрационные сценарии.
Рабочие страницы Кабинетов сюда не входят. API компонентов описан в [components/README.md](../components/README.md),
общая структура и сборка — в [structure.md](../../docs/project/structure.md).

Точка запуска — `DevApplication`, корень пакетов — `tech.testsys.web.devapp`. У приложения свои `AppShell`,
Spring-конфигурация, локаль, frontend и обработчик HTTP 404. Оно использует библиотеку components и локализацию,
а не исходники или артефакт основного приложения. Большая фабрика текстов и визуальная реализация 404 общие.

## Запуск и проверка

```bash
./gradlew :testsys-web:dev-app:bootRun -Pdetekt.autoCorrect=false --args='--spring.profiles.active=dev'
```

По умолчанию используется порт 8081. Главная витрина — `/dev/showcase`; тематические страницы — `states`,
`forms`, `overlays`, `display` и `header` под этим адресом. Профиль `dev` открывает витрину; без него ее адреса
возвращают 404. Ошибки загрузки и фиктивные данные в демонстрациях не являются рабочими сценариями Системы.

```bash
./gradlew :testsys-web:dev-app:build -Pdetekt.autoCorrect=false
```

Frontend находится в `src/main/frontend/`; generated и build-файлы принадлежат этому модулю.
Витрина — примеры совместного использования и памятка существующих элементов, не эталон и не источник правил.
Правила оформления — в [ui-design.md](../../docs/project/ui-design.md), API и контракты — в components.
`/dev/showcase/foundations` иллюстрирует палитру, шрифты, радиусы, тени, движение и бренд из общих ресурсов.
Все иконки представлены на главной витрине; тематические страницы сохраняют поля, compact filters, состояния,
оверлеи, отображение, таблицы, упорядочивание и quiz-компоненты.

## Демонстрация сценариев

`/dev/demo/:screen?` — Kotlin DSL на данных пакета `demo`. Ключи: `home`, `login`, `<role>.<section>`;
полный список разделов принадлежит `DemoSession.kt`. Меню содержит восемь Кабинетов, URL и Back/Forward работают
через маршрутизатор Vaadin. Вкладки подразделов находятся под полным заголовком Кабинета в PageHead
и используют точное совпадение параметров маршрута. Короткие информационные поля показываются парами
на общей сетке, длинные описания и логи занимают строку; регистрация группирует псевдоним и Роль.
Заголовок Кабинета в меню ведёт в его Обзор; поиск открывает и фильтрует
ту же панель. Неизвестный ключ открывает Главную. Без профиля dev эти маршруты возвращают 404.

Fixtures и переходы принадлежат Kotlin demo model; данные и выбранные объекты живут в одном UI между разделами,
сброс возвращает fixtures. Модель не подключает БД, бизнес-операции или production security.
Результат действия показывает один стандартный toast успеха/ошибки из DemoContext. Сообщение не хранится
в UI-состоянии и не создаёт блок страницы; навигация, фильтры и фоновые обновления не повторяют feedback.
Ошибки полей остаются внутри формы, подтверждение регистрации сохраняет свой функциональный блок.
Вход по КД, регистрация Ученика/Организатора, подтверждение и одноразовое восстановление показывают mock письма
внутри демонстрации. Существующие Кабинеты сохраняют контекст Роли и сведения выбранных объектов.

Организатор создаёт Соревнование и Участников через Dialog из действий шапки соответствующего блока.
Количество — целое положительное, default 3; максимум 100 за вызов только для устойчивости демонстрации,
не лимит Системы. Добавление доступного существующего Тура имеет отдельный Dialog.
CSV содержит всю матрицу Участников и Задач выбранного Тура независимо от фильтра/страницы.

Все списки используют стандартные TableFilters, обычные поля/Binder и таблицу с pageSize 10.
Defaults пустые; фильтрация начинается с уже ограниченного контекстом набора.
Контракт применения, сброса и валидации описан в [components/README.md](../components/README.md),
раздел «Поля фильтров таблицы». Выбранные сведения находятся вне отфильтрованной таблицы. Период использует штатный dateRangeInput и календарь.
Результат Судьи сохраняет выбор Решения и сведения/логи/видеозапись; Наблюдатель и Организатор используют
одну матрицу лучших баллов. История Ресурса — таблица с фильтрами и скачиванием версии.
Footer общий. Отправка файла демонстрационная: содержимое не сохраняется, состояния Queue/Checking/Checked
меняются локально; скачиваемые материалы явно являются примерами.

Чистые model/navigation/filter сценарии проверяются в `src/test/kotlin/.../demo/`, формы и маршруты — Karibu.

Cookie сессии называется `TESTSYS_DEV_SESSION`. Отдельное имя позволяет открывать оба приложения
на одном хосте одновременно без перезаписи сессии другого приложения.
