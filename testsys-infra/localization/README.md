# Локализация

Документ описывает, как устроена локализация в проекте: формат ключей, поддерживаемые типы плейсхолдеров,
словарь `glossary` и правила использования сгенерированного API. Он предназначен для всех, кто пишет строки,
которые видит пользователь. Пошаговое добавление сообщения или региона — в
[add-localization.md](../../docs/guides/add-localization.md).

Локализация — это типобезопасный API, сгенерированный из ICU `MessageFormat`-паттернов. Рантайм-код **никогда
не работает со строковыми ключами**: каждое сообщение — это метод на сгенерированном классе с типизированными
параметрами. Опечатка в имени аргумента, забытая ветка `select`, лишний или пропущенный плейсхолдер — ошибка
компиляции.

Модуль: `:testsys-infra:localization`. Публичная точка входа — сгенерированный
`tech.testsys.infra.localization.Localization.forRegion(region)`.

## Где что лежит

| Что                        | Где                                                                |
|----------------------------|--------------------------------------------------------------------|
| Ресурсы (`*.properties`)   | `testsys-infra/localization/src/main/resources/localization/`      |
| Рантайм                    | `testsys-infra/localization/src/main/kotlin/.../bundle`            |
| Кодген                     | `testsys-infra/localization/src/codegen/kotlin/...`                |
| Тесты кодгена              | `testsys-infra/localization/src/codegenTest/kotlin/...`            |
| Сгенерированный код        | `build/generated/source/localization/main/kotlin/`                 |

Имя файла ресурсов — идентификатор `SupportedRegion` в верхнем регистре (`RU.properties`, `EN.properties`, …).
Кодировка — UTF-8. Генерация привязана к `compileKotlin` модуля.

## Формат ключа

Ключ имеет вид `<bundle>.<segment>[.<segment>…]=<ICU pattern>`.

- Всё **до первой точки** — `bundle`, превращается в имя класса (`snake_case → PascalCase`).
- Всё **после первой точки** — имя метода (`dot`/`snake_case → camelCase`, сегменты сливаются).
- Ключ без точки или конфликт имён после нормализации — ошибка кодгена.

| Ключ                      | Класс         | Метод            |
|---------------------------|---------------|------------------|
| `task.deadline.in_days`   | `Task`        | `deadlineInDays` |
| `task.deadline.passed`    | `Task`        | `deadlinePassed` |
| `glossary.task`           | `Glossary`    | `task`           |

Все существующие ключи — в [RU.properties](src/main/resources/localization/RU.properties).

## Поддерживаемые типы плейсхолдеров

| ICU                                       | Kotlin-параметр                                             |
|-------------------------------------------|-------------------------------------------------------------|
| `{name}`                                  | `String`                                                    |
| `{n, number}`, `{n, number, percent}`     | `Number`                                                    |
| `{when, date}`, `{when, time}`            | `java.time.Instant`                                         |
| `{n, plural, …}`, `{n, selectordinal, …}` | `Int`                                                       |
| `{n, spellout}`, `{n, ordinal}`           | `Int`                                                       |
| `{x, select, A {…} B {…} other {…}}`      | сгенерированный `enum class` (объединение веток + `OTHER`)  |

`select` всегда требует ветку `other` — это требование ICU, кодген ничего не добавляет молча.

Конфликт типов одного плейсхолдера между регионами — ошибка кодгена с указанием обоих ключей.

## Объединение сигнатур между регионами

Сигнатура метода — **объединение** плейсхолдеров по всем регионам:

- плейсхолдер есть только в одном регионе → параметр всё равно в сигнатуре, в других регионах он молча
  игнорируется на рантайме;
- ветки `select` — объединение по всем регионам;
- если ключ отсутствует в каком-то регионе — ошибка кодгена (всё переводим).

## Glossary: словарь падежей и склонений

В `Glossary` лежат **только доменные термины** — слова, которые повторяются во многих сообщениях и должны
склоняться единообразно (Задача, Пользователь, …). Это нужно, чтобы собирать осмысленные русские фразы вроде
«Удалить 5 задач» вместо «Удалить 5 задача».

**Всё остальное форматируем на месте**, прямо в сообщении-ключе:

- разовая фраза с числом или склонением, которая не переиспользуется, пишется одним ICU-паттерном в своём ключе
  (см. `task.deadline.in_days`), а не разбивается на «общую» часть + `glossary`;
- статичные строки без параметров — просто текст в `.properties`;
- собирать предложение через `glossary` имеет смысл, только если вставляемое слово встречается ≥2–3 раз
  в разных контекстах. Иначе это лишний уровень косвенности, и такое сообщение сложнее переводить на языки
  с другой структурой словосочетания.

Не добавляйте в `glossary` слова «на будущее» — заведём, когда понадобится второе место.

Структура термина — `select` по падежу с вложенным `plural` по количеству. Образец — `glossary.task`
в [RU.properties](src/main/resources/localization/RU.properties).

- Термин содержит **только само слово, без числа**: число подставляет вызывающая сторона в основном сообщении.
  Поэтому внутри plural-веток **не используем `#`**.
- Падежи кодируем латинскими сокращениями: `nom`, `gen`, `dat`, `acc`, `ins`, `loc`.
- Ветка `other` на уровне `select` обязательна по ICU — кладём туда форму именительного падежа как безопасный
  fallback на случай, если в код просочится `TaskCase.OTHER`.

### Имя плейсхолдера для glossary-термина

Если плейсхолдер предназначен для подстановки термина из `glossary.*`, его имя начинается с `glossary`
и заканчивается именем термина в camelCase: `{glossaryTask}`, `{glossaryUser}`. Правило действует для всех
`.properties` во всех регионах. Образец — ключ `task.result`.

Зачем:

- при чтении паттерна сразу видно, что в слот подставляется не «любая строка», а результат `l.glossary.<term>(…)`;
- поиск по `{glossary` находит все места, где словарь реально подключён;
- параметр в Kotlin получает осмысленное имя (`glossaryTask: String`).

| Плохо                              | Хорошо                                     |
|------------------------------------|--------------------------------------------|
| `{count, number} {term}`           | `{count, number} {glossaryTask}`           |

## Использование в коде

Термин из словаря получается отдельным вызовом и передаётся в основное сообщение:

```kotlin
val l = Localization.forRegion(SupportedRegion.RU)
l.task.result(count = n, glossaryTask = l.glossary.task(case = Glossary.TaskCase.GEN, count = n))
```

Правила:

- **Никаких строковых ключей наружу.** Если хочется передать ключ в другой слой — передавайте лямбду
  `(Localization) -> String`.
- `Localization.forRegion(region)` дёшев, но инстанс можно кешировать на запрос или сессию.
- Параметры всегда передаются по имени — это часть контракта.

## Чего не делаем

- **Не конкатенируем переводы вручную.** «Удалить » + count + " задач" ломается на других языках и числах.
  Всё через `MessageFormat` и `glossary`.
- **Не используем `String.format` и интерполяцию** для пользовательских строк.
- **Не правим и не коммитим сгенерированный код** в `build/generated/`: он перегенерируется при каждой сборке.
- **Не оставляем строки без локализации** в продовом коде. Если перевод ещё не готов — заводим ключ
  с заглушкой в `RU.properties`, а не хардкод в Kotlin.
