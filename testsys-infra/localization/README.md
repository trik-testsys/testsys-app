# Локализация

Документ описывает модуль `:testsys-infra:localization`: зачем он нужен, как устроен, какую работу делает наш код,
а какую ICU4J, где что лежит и по каким правилам пишется код модуля. Он предназначен для тех, кто меняет модуль,
обновляет ICU или разбирается в ошибке сборки локализации. Как написать сообщение и добавить регион (формат
сообщений, типы параметров, ограничения и примеры) — в [add-localization.md](../../docs/guides/add-localization.md).

## MF2 и ICU

- **MF2 (Unicode MessageFormat 2)** — стандарт Unicode для записи локализуемых сообщений. Одно сообщение описывает
  подстановку значений, выбор варианта по числу или строке (множественное число, род), форматирование чисел, дат
  и валют. Преемник классического ICU MessageFormat; проект следует версии спецификации из LDML 48.
  Обзор — [messageformat.unicode.org](https://messageformat.unicode.org/), спецификация —
  [LDML 48, часть 9: MessageFormat](https://www.unicode.org/reports/tr35/tr35-messageFormat.html).
- **ICU (International Components for Unicode)** — библиотеки Unicode и интернационализации для C/C++ (ICU4C)
  и Java (ICU4J): форматирование чисел и дат, правила множественного числа, часовые пояса, числа прописью.
  Данные о языках и регионах ICU берёт из [CLDR](https://cldr.unicode.org/). Проект использует ICU4J, в том
  числе его реализацию MF2. Сайт — [icu.unicode.org](https://icu.unicode.org/), руководство —
  [ICU User Guide](https://unicode-org.github.io/icu/userguide/), раздел о MF2 —
  [MessageFormat 2.0](https://unicode-org.github.io/icu/userguide/format_parse/messages/mf2.html).

## Зачем модуль

Сообщения модуля пишутся на MF2. На нём одним сообщением выражаются множественное число,
склонения, числа, даты и валюты по правилам CLDR, а форматирует сообщения ICU4J. Но ICU4J MF2 напрямую из продового
кода не вызывается, потому что:

- **Ошибки видны только при форматировании.** У ICU сообщение — строковый ключ и `Map<String, Any>` аргументов:
  опечатка в ключе, пропущенный параметр или неверный тип всплывают на проде. Модуль генерирует по методу
  на сообщение с типизированными параметрами, поэтому неверный вызов не скомпилируется.
- **ICU4J 78.1 молча ошибается.** Он игнорирует часть опций спецификации, отбрасывает разметку, никогда не выбирает
  ключ `other` числового селектора и передаёт аргументы сообщения числовым функциям как опции. Такое сообщение
  выглядит правильным, а выводит не то. Кодген отклоняет при сборке всё, что ICU выполнит не так, поэтому он
  строже спецификации.
- **Неполное сообщение видно только на редком числе.** Забытая категория `few` проявится только на «3 задачи».
  Сборка проверяет, что каждая достижимая категория покрыта явным вариантом.
- **Регионы расходятся.** Ключ, которого нет в одном из регионов, или несовместимые типы параметров в разных
  регионах — ошибка сборки, а не пустая строка на рантайме.
- **MF2 API ICU — technology preview** (`@Deprecated`), и в ICU 79 меняются сигнатуры функций. Модуль изолирует
  этот API в нескольких файлах; сгенерированный код и его вызывающие от него не зависят.
- **Доменные слова должны склоняться одинаково.** Термины (`glossary.*`) и функция `:term` хранят формы слова
  в одном месте на регион, а Kotlin передаёт только число.
- **Даты не должны молча показываться в зоне сервера.** Часовой пояс — обязательный параметр контекста.

## Как устроено

Модуль работает в две фазы. При сборке кодген превращает `.properties` в Kotlin-код; на рантайме сгенерированные
методы передают сообщение и аргументы ICU4J.

### Сборка

Задача `generateLocalization` запускается перед `compileKotlin` и вызывает `Main.kt` для
`src/main/resources/localization` с пакетом продукта `tech.testsys.infra.localization`. Задача
`generateLocalizationExamples` запускается перед `compileTestKotlin` и тем же `Main.kt` генерирует API набора примеров
`src/test/examples/localization` в пакет `tech.testsys.infra.localization.examples`, который видят только тесты.
Оба каталога остаются входами задач генерации. Исходные `localization/**`, включая `regions.properties`
и файлы сообщений, не упаковываются в jar: сведения о регионах и сообщения встроены в сгенерированный код,
а рантайм не читает исходные файлы.
Конвейер `LocalizationCodegen`:

| # | Шаг                                                                                                        | Чей код                   | Где                                  |
|---|------------------------------------------------------------------------------------------------------------|---------------------------|--------------------------------------|
| 1 | Прочитать `regions.properties` и файлы бандлов каждого региона строго, а не как `java.util.Properties`, который молча прощает ошибки записи: правила записи и файла бандла — в разделах «Запись в .properties» и «1. Выбрать ключ и файл бандла» [add-localization.md](../../docs/guides/add-localization.md) | наш                       | `source`                             |
| 2 | Разобрать синтаксис MF2                                                                                    | ICU `MFParser`            | фасад `mf2/parser/Mf2Parser.kt`      |
| 3 | Перевести дерево ICU в собственную модель сообщения                                                        | наш                       | `mf2/parser`, `mf2/model/Message.kt` |
| 4 | Разрешить сообщение: область видимости, функцию и объединённые опции каждого выражения, как это сделает ICU | наш                       | `mf2/validator/Resolver.kt`          |
| 5 | Проверить правила: функции и опции MF2, ограничения проекта, обходы ICU 78.1, полноту выбора, термины        | наш                       | `mf2/function`, `mf2/validator`, `mf2/icu` |
| 6 | Вывести типы параметров и слить сигнатуры регионов                                                         | наш                       | `signature`                          |
| 7 | Проверить имена и сгенерировать Kotlin                                                                     | наш, KotlinPoet           | `emitter`                            |

Кодген собирает все ошибки запуска и выводит их одним списком, тексты ошибок — в `Problems.kt`. От ICU кодгену
нужны только парсер (шаг 2), разбор числовых скелетов и единиц `NumberFormatter.forSkeleton` и данные CLDR:
категории множественного числа, наборы правил RBNF, единицы измерения, валюты, календари и системы счисления для
проверки значений опций. Проверки работают с собственной моделью, а не с `MFDataModel` ICU, поэтому от technology
preview зависит один файл.

### Рантайм

`Localization.forRegion(region, timeZone)` создаёт бандлы региона; метод бандла передаёт ключ и аргументы
(значения Kotlin и `java.time`) в `MessageRuntime`.

| Что делается                                                                    | Чей код                                           |
|---------------------------------------------------------------------------------|---------------------------------------------------|
| Методы с типизированными параметрами, таблица сообщений и зон каждого региона   | сгенерированный (`Localization`, бандлы, `LocalizationMessages`) |
| Кеш форматтеров на пару (регион, ключ), перевод `Instant` в `ZonedDateTime` в зоне сообщения, передача зоны-смещения как `GMT±hh:mm` | наш: `runtime/MessageRuntime.kt` |
| Выбор варианта, форматирование чисел, дат и валют, категории CLDR               | ICU4J `MessageFormatter`                          |
| Функции `:term`, `:spellout`, `:ordinal`, `:unit`                               | наш: `runtime/function`, регистрируются в ICU для каждого региона |

`Instant` переводится в `ZonedDateTime` на нашей стороне: ICU4J 78.1 не форматирует `Instant` и игнорирует опцию
`timeZone` для значений с зоной. Зону-смещение, которую ICU не знает (`+03:00`, `UTC+03:00`), рантайм передаёт как
`GMT+03:00`: ICU4J 78.1 разбирает смещение только с префиксом `GMT`, а другую зону молча показывает по Гринвичу.
Форматтер работает с `ErrorHandlingBehavior.STRICT`: сборка уже проверила
сообщения, и ошибка на рантайме — дефект. Изоляция bidi — `NONE`, потому что API возвращает простой `String`.

## Ключевые решения

- **Лучше отказать при сборке, чем вывести не то.** Каждое правило, которое обходит поведение ICU4J 78.1, лежит
  в пакете `mf2/icu`, и каждый файл называет обходимое поведение и тест, который его закрепляет. Ограничения
  проекта (имена переменных, неиспользуемый `.input`, ключи селекторов, одна зона на аргумент-дату) лежат
  в `mf2/validator/rules`, а ограничения пользовательской функции, которые диктует её рантайм, — в её объекте
  в `mf2/function`.
- **Белый список опций закреплён тестами.** Опция функции разрешена, если она есть в спецификации MF2 и ICU её
  применяет: опции функции (опции спецификации и `icu:skeleton`) — в объектах `mf2/function`, исключения —
  в `mf2/icu/IgnoredOptions.kt`.
  [OptionHonouredTests.kt](src/codegenTest/kotlin/tech/testsys/infra/localization/codegen/mf2/icu/OptionHonouredTests.kt)
  проверяет, что белый список равен набору опций, которые действительно меняют вывод.
- **Одно знание — в одном месте.** Всё о функции MF2 (опции, операнд, тип параметра, может ли она быть
  селектором) — в её объекте в `mf2/function`; правило проверки — один класс: ограничение проекта
  в `mf2/validator/rules`, обход ICU в `mf2/icu`, проверка ссылок на термины в `mf2/validator/term`.
- **Kotlin передаёт смысл, сообщение выбирает форму.** Падеж, число и порядок слов определяет сообщение региона,
  поэтому API термина не генерируется, а селектор `:string` становится `enum`.
- **Кодген работает с содержимым файлов, а не с файловой системой**, поэтому его тесты не читают диск.

## Где что лежит

Все пути — относительно `testsys-infra/localization`.

| Что                                   | Где                                                                                   |
|---------------------------------------|---------------------------------------------------------------------------------------|
| Регионы и сообщения                   | `src/main/resources/localization/`: `regions.properties`; `<языковой тег>/<bundle>.properties` — сообщения бандла в регионе, например `ru-RU/todo.properties` |
| Набор примеров                        | `src/test/examples/localization/`: та же раскладка, по примеру на каждую поддерживаемую функцию и конструкцию |
| Рантайм                               | `src/main/kotlin/.../runtime`: `MessageRuntime.kt`; `function/` — пользовательские функции |
| `LocaleData` и `SupportedRegion`      | `src/main/kotlin/.../bundle` (`SupportedRegion` генерируется)                         |
| Opt-in-маркер внутреннего API         | `src/main/kotlin/.../InternalLocalizationApi.kt`                                      |
| Кодген                                | `src/codegen/kotlin/...`, пакеты ниже                                                 |
| Тесты кодгена                         | `src/codegenTest/kotlin/...`, те же пакеты                                            |
| Тесты рантайма и golden-тесты         | `src/test/kotlin/...`; golden-тест набора примеров — в пакете `examples`              |
| Сгенерированный код                   | `build/generated/source/localization/main/kotlin/`                                    |
| Сгенерированный код набора примеров   | `build/generated/source/localization/test/kotlin/`, пакет `tech.testsys.infra.localization.examples` |

Пакеты кодгена (`tech.testsys.infra.localization.codegen`):

| Пакет или файл           | Что                                                                                       |
|--------------------------|-------------------------------------------------------------------------------------------|
| `Main.kt`                | CLI: читает каталог ресурсов, запускает конвейер, пишет файлы API в заданный пакет         |
| `LocalizationCodegen.kt` | Конвейер: регионы → файлы → анализ каждого региона → слияние → имена → вывод              |
| `Problems.kt`            | Каталог текстов всех ошибок                                                               |
| `Diagnostics.kt`         | Контекст ошибок сообщения и файла, сбор всех проблем запуска                             |
| `source`                 | Чтение `regions.properties` и `.properties`, проверка набора файлов                       |
| `mf2/model`              | Модель сообщения (`Message.kt`) и разрешённая модель (`Resolved.kt`)                      |
| `mf2/parser`             | Фасад парсера ICU `Mf2Parser.kt`                                                          |
| `mf2/function`           | По объекту на MF2-функцию, реестр `Functions`; `option/` — опции и проверки их значений   |
| `mf2/validator`          | `Resolver`, анализатор сообщения и региона, список правил; `rules/` — по классу на правило, `completeness/` — полнота выбора, `term/` — термины |
| `mf2/icu`                | Обходы особенностей ICU4J 78.1                                                            |
| `signature`              | Типы параметров сообщения и их слияние между регионами                                    |
| `emitter`                | Генерируемые типы: по эмиттеру на тип, имена и их проверка                                |

## Правила кода модуля

- Внутренний API модуля помечен opt-in-маркером `@InternalLocalizationApi` (`@RequiresOptIn`): все объявления
  пакета `runtime`, сгенерированный `LocalizationMessages` и конструкторы бандлов. Снаружи модуля используются
  только `Localization`, бандлы, `SupportedRegion` и `LocaleData`. Сгенерированные классы бандлов,
  `Localization.forRegion`, `LocaleData.forRegion` и тесты рантайма объявляют `@OptIn(InternalLocalizationApi::class)`;
  новое объявление в `runtime` само помечается маркером.
- В `main` пакет `com.ibm.icu.message2` импортирует только пакет `runtime` с подпакетами, в кодгене — только
  `mf2/parser/Mf2Parser.kt`. Каждый такой файл подавляет предупреждения об устаревании на уровне файла.
  Сгенерированный код этот API не использует.
- Внутренний API ICU `com.ibm.icu.impl` в кодгене импортирует только пакет `mf2/icu`.
- Имена функций и опций MF2 записываются литералами только в `mf2/function`, `mf2/function/option` и `mf2/icu`;
  остальной код ссылается на объекты и константы.
- ICU закреплён на `78.1`. Обновление ICU начинается с тестов `mf2/icu` и `OptionHonouredTests`: они покажут,
  какие обходы стали лишними и какие опции ICU начал или перестал применять.
- Source set модуля `main`, `test`, `codegen`, `codegenTest` проверяются общим механизмом Detekt;
  устройство агрегаторов и команды проверки — в разделе «Сборка» [structure.md](../../docs/project/structure.md).
- Сгенерированный код в `build/generated/` (API продукта и API набора примеров) не правится и не коммитится: он
  перегенерируется при каждой сборке.

## Использование в коде

Сообщение вызывается методом сгенерированного бандла с именованными параметрами. Образец вызовов всех ключей
продукта — golden-тест [LocalizationTests.kt](src/test/kotlin/tech/testsys/infra/localization/LocalizationTests.kt),
образец вызова каждой функции и конструкции —
[ExampleLocalizationTests.kt](src/test/kotlin/tech/testsys/infra/localization/examples/ExampleLocalizationTests.kt).

- **Никаких строковых ключей наружу.** Чтобы передать сообщение в другой слой, передавайте лямбду
  `(Localization) -> String`.
- Kotlin передаёт только смысл: число, значение, вариант `enum`.
- Параметры передаются по имени — это часть контракта.
- **Один экземпляр на поток.** `Localization` с его бандлами и `LocaleData` не передаются между потоками: каждый
  поток создаёт свой через `forRegion`. `Localization.forRegion` дёшев — форматтеры сообщений кешируются на регион
  и ключ внутри модуля.
- Пользовательские строки не собираются конкатенацией, `String.format` или интерполяцией и не хардкодятся в Kotlin:
  всё — одним MF2-сообщением. Как быть, если перевод не готов, — в шаге «4. Добавить сообщение во все регионы»
  [add-localization.md](../../docs/guides/add-localization.md).

Текущий способ задания текстов веб-интерфейса описан в
[ui-design.md](../../docs/project/ui-design.md).
